# PixelPin 截图贴图工具

PixelPin 是一款使用 .NET 8 和 WPF 独立实现的 Windows 原生截图与桌面贴图工具，功能对标 Snipaste、PixPin 等主流截图贴图软件。界面为简体中文，截图、历史记录和诊断数据默认只保存在本机。

## 运行

~~~powershell
dotnet run --project .\src\PixelPin.App\PixelPin.App.csproj
~~~

程序启动后常驻系统托盘。使用托盘菜单或按 F1 开始区域截图。快捷键同时使用 Windows 全局热键和按键兼容通道，部分会吞掉普通键盘消息的应用也可以触发截图；兼容通道只匹配已配置的按键，不记录或上传键盘内容。

可以使用 `--settings`、`--diagnostics`、`--history`、`--windows` 或 `--stickers` 直接打开对应工具窗口。排查快捷键冲突时，可以追加 `--no-hotkeys` 禁用全局快捷键。

## 默认快捷键

| 快捷键 | 功能 |
| --- | --- |
| `F1` | 区域截图（松开鼠标后显示操作条） |
| `F3` | 区域截图并直接贴图（松开鼠标即完成） |
| `Ctrl+F1` | 全屏截图（所有显示器，直接复制） |
| `Ctrl+F3` | 把剪贴板中的图片贴到桌面 |
| `Ctrl+Alt+P` | 切换最后一张贴图的鼠标穿透 |
| `Shift+F3` | 关闭所有贴图 |

全部快捷键都可以在设置页修改：**点击输入框后直接按下想要的组合键**即可录制，`Backspace` 清除，`Esc` 撤销本次录制。保存时会检查语法、重复占用和系统冲突，失败时保留原有快捷键。

## 截图

- 每块显示器一个独立覆盖层，基于物理像素桌面截图，支持混合 DPI。
- 鼠标悬停时高亮指针所在窗口并显示标题，**单击即可直接截取该窗口**（按窗口真实边界裁剪）。
- 拖动框选时自动吸附到附近窗口边缘；`Ctrl+A` 选择整块显示器。
- **方向键微调选区**：方向键移动 1 像素，`Shift+方向键` 调整对应边或角，按住 `Ctrl` 步长变为 10 像素，用于像素级对齐。
- 实时放大镜、像素坐标和 RGB 取色。
- 选区显示真实像素尺寸，操作条提供复制、保存、贴图、编辑、全屏和取消。
- `Enter`/`Ctrl+C` 复制、`Ctrl+S` 保存、`P` 贴图、`E` 编辑、右键或 `Esc` 取消。

## 标注编辑

矩形、椭圆、直线、箭头、画笔、高亮、马赛克、模糊、序号、文字，支持自定义颜色、线宽和字号，以及撤销/重做（各 40 步）、清除和缩放（`Ctrl+±`、`Ctrl+0`、适应窗口）。

马赛克和模糊会把处理结果烘焙成位图覆盖层，因此导出的 PNG 与预览逐像素一致，而不是仅做视觉近似。

## 美化导出

`Ctrl+B` 打开美化面板，为截图加上圆角、柔和阴影、渐变背景和内边距，适合直接分享。内置浅灰、纯白、暖阳、深海和午夜五种背景预设，留白、圆角和阴影都可单独调整。

预览与导出使用同一个渲染器，所见即所得。留白不足时收窄阴影而不是撑大画布，保证阴影不会被裁掉。美化结果适用于复制、保存、另存为、贴图和完成等全部导出路径。

## 贴图

- 无边框置顶窗口，拖动移动、滚轮缩放、右下角手柄调整大小、双击关闭。
- **拖动时自动对齐**：吸附到其他贴图的边缘和中心线，以及屏幕边缘和屏幕中心，并显示对齐辅助线；按住 `Alt` 拖动可临时关闭吸附。边缘只和边缘对齐、中心只和中心对齐，所以贴图不会被一次吸附推得离开屏幕。
- 贴图不会被拖到够不着的地方：推到屏幕边缘时每个方向至少保留 48 DIP 可见，可以推到几乎看不见，但永远还能再抓回来。
- 旋转 90° 使用布局变换，图片始终保持真实比例，不会被拉伸变形。
- 可开关原始比例锁定、阴影、置顶层级和鼠标穿透（穿透后有恢复入口）。
- `Ctrl+拖动` 可把贴图直接拖到其他程序（浏览器、聊天工具、编辑器）。
- 右键菜单支持复制、保存 PNG/JPEG、另存为、旋转、比例、阴影、置顶和穿透。
- 支持命名分组、批量关闭、层级控制和贴图管理器。
- 拖入图片文件或粘贴剪贴板图片即可创建新贴图。

## 文字识别（OCR）

编辑器里的「OCR」按钮（或 `Ctrl+Shift+O`）会识别当前截图中的文字，在对话框中查看、编辑和复制。使用 Windows 自带的 OCR 引擎，识别语言可切换，默认优先中文。复制支持「复制全部」（保留换行）和「复制为一行」两种方式。

中文识别结果不带多余空格：识别器按「每字一词」返回并用空格拼接，直接使用会得到 `截 图 贴 图`，PixelPin 会按词重新组装并逐对判断空格，因此中英混排也能得到自然结果。

系统缺少 OCR 组件或未安装任何识别语言包时，会明确说明原因并给出安装路径，不会返回一个看起来成功的空结果。

## 遮挡窗口截图

被其他窗口遮住的窗口也能截到它自己的内容。窗口截图按三条路线依次尝试：

1. **图形捕获**（`Windows.Graphics.Capture`）—— 直接读窗口自己合成后的画面。不受遮挡影响，硬件加速窗口能正确截到，圆角保持圆角，窗口跑出屏幕边缘也能截全。
2. **窗口自绘**（`PrintWindow` + `PW_RENDERFULLCONTENT`）—— 让窗口把自己画进一张位图，不需要 GPU，但用 DirectComposition 渲染的窗口会静默返回黑图。
3. **屏幕裁剪** —— 就是用户正在看的画面。窗口完全可见时这是最准确也最便宜的一条，被遮挡时它会截到盖在上面的窗口，所以只在窗口大部分可见时才会用到。

顺序由 `WindowCapturePlanner` 决定并可单测：**用户能完整看到的窗口走屏幕裁剪，其余情况先走不依赖层叠关系的路线**。

每一路线拿到结果后都会做质量检查再决定是否接受，全透明、全黑、尺寸不符都会被拒绝。质量检查用平台自身的返回值区分「窗口没渲染出来」和「窗口本来就是纯色」，因此空白窗口仍可正常截图，而硬件加速窗口返回的全黑画面一律拒绝。三条路线全部失败时会逐条说明原因（例如「图形捕获：窗口已最小化；窗口自绘：返回全黑画面」），而不是交出一张别的窗口的截图。

图形捕获保留窗口真实的 alpha，所以圆角窗口截出来仍是圆角。捕获时不会画入鼠标指针，被捕获窗口周围那圈系统黄框也会被抑制。

## 滚动截图

框选一块可以滚动的内容，程序自动向下滚动并把每一帧拼成一张长图。工具栏的「长截图」按钮和 `L` 键都可以，滚动截图快捷键则直接进入滚动模式：拖完选区就自动开始。

**滚动偏移由像素测出来，不按滚轮格数推算。** 每个应用滚一格滚多远都不同，平滑滚动下同一次滚动的位移也不固定，所以每一帧都拿前后两张图做重叠匹配，测出真实位移再拼接。

**验证不了就拒绝。** 以下情况会停下并说明原因，而不是交出一张看起来正常、其实有重复或缺口的长图：

- 内容存在重复图案（同一画面在两个位置都吻合，选哪个都是猜）；
- 前后帧找不到一致的衔接位置（内容变了而不是滚动了）；
- 滚动幅度接近选区高度（重叠太少，无法确认连续）。

因为高度上限或中途无法确认偏移而停下时，已经拼好的部分仍然保留，同时告诉你停在哪里、为什么停 —— 否则你很容易以为那就是全部内容。

纯色页面滚动前后完全一样，从像素里读不出偏移，此时会按「已到末尾」结束，交出一张单帧截图，而不是编一个偏移去拼。

**选区请框在真正会滚动的内容上。** 如果框进了大面积的固定区域（不滚动的侧栏、标题栏），能用来对齐的部分就变少，程序会在无法确认时拒绝并告诉你原因。含滚动条本身没有问题，程序能把它从判定里排除掉。

## 其他功能

- 当前窗口截图和可见窗口选择器。
- 浅色 / 深色 / 跟随系统三种外观，设置页里选择即可预览，标题栏与圆角由系统一起切换。
- 本地历史记录：搜索、标签、收藏、重新贴图、复制、保存、编辑和删除，支持可配置的数量与磁盘缓存上限。
- 本地隐私与诊断页，带容量上限的滚动日志；截图、剪贴板内容和日志都不会上传。
- 开机启动、保存目录、文件名模板、设置导入导出。
- WebP 导出在当前构建不可用时会明确提示，不会伪造结果。

## 便携版

便携版无需安装，解压后直接运行 `PixelPin.exe`。使用下面的脚本可以生成自包含的单文件程序和 ZIP 压缩包：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\Publish-Portable.ps1
```

输出目录为 `artifacts\PixelPin-win-x64-portable`，ZIP 文件名带有当前版本号。设置和历史记录保存在当前 Windows 用户的 `%LocalAppData%\PixelPin`，删除程序目录不会删除这些本地数据。

## 验证

~~~powershell
dotnet build PixelPin.sln -c Release
dotnet run --project .\tests\PixelPin.Tests\PixelPin.Tests.csproj -c Release
~~~

上面的命令运行不依赖桌面的自动检查（25 项），覆盖设置规范化与可移植性、主题偏好解析与回退、快捷键解析与冲突检测、快捷键录制与解析往返、选区几何与窗口吸附、选区键盘微调、贴图缩放几何、贴图对齐吸附、像素化与模糊、美化布局与阴影收敛、OCR 文本组装与脚本判定、OCR 不可用原因、窗口渲染质量判定、遮挡程度计算、窗口截图路线优先级、滚动截图的偏移测量与拒绝判定，以及文件名展开。

界面改版另有一个离屏渲染检查（`tests\PixelPin.UiRender`），它加载真实的 `App.xaml` 资源，把每个工具窗口在 96 与 192 DPI 下渲染出来，并断言截图看不出来的东西：滑块是否真的接上了、复选框的勾是否画出来、每对文字与底色的对比度（浅色与深色各测一遍）、当前工具是否唯一选中、覆盖层工具条是否在屏幕内、两套令牌的键是否完全一致、DWM 标题栏是否真的变深、Tab 顺序是否与视觉顺序一致、焦点环覆盖，以及 150% 缩放下的最小尺寸是否会溢出。渲染结果写入 `artifacts\ui-review`。

~~~powershell
dotnet run --project .\tests\PixelPin.UiRender -c Debug
~~~

在交互式桌面上还可以运行桌面探针，它会真实截屏、枚举 z 序窗口、渲染截图覆盖层、移动鼠标验证窗口高亮、驱动方向键微调、驱动标注编辑器并检查导出像素、验证两张真实贴图的吸附与辅助线、**用真实鼠标事件按下、移动、抬起拖动一次贴图并断言它确实跟着指针走了**、校验美化导出的像素、向设置页真实派发按键验证快捷键录制链路、渲染真实文字并用 OCR 读回比对，以及**叠放两个已知颜色的窗口来证明遮挡截图走的是窗口自身的画面而不是盖在上面的窗口**——三条路线各自验证：图形捕获返回下层窗口的颜色且帧内没有捕获黄框，窗口自绘同样返回下层颜色，屏幕裁剪则返回上层颜色（这正说明遮挡是真实的、对比有意义）。图形捕获被声明为不可用时，探针还会验证整条链会诚实降级到窗口自绘并且仍然拿到下层窗口的内容。

滚动截图则由一个真实的可滚动窗口验证：内容每一行都带一个唯一颜色，因此拼接结果可以**逐行解码还原成行号**。探针要求行号严格每次加一 —— 重复的行、缺失的行、用错偏移拼接，三种错误都会破坏这个性质。实测 22 帧拼出 2000 行，跨度和源内容完全一致。同一个探针还会用周期性重复的内容验证**拒绝路径**：此时必须只出 1 帧、高度不变，并给出「内容存在重复图案」的原因，而不是拼出一张内容重复的长图。

dotnet run --project .\tests\PixelPin.Tests\PixelPin.Tests.csproj -c Release -- --desktop-probe .\artifacts\probe
~~~
